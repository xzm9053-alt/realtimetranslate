================================================================================
          独立闭源软件·通用版本更新检测与视频引流体系技术指南
================================================================================

【适用场景】
1. 闭源/私有成品应用，严禁暴露 GitHub 仓库或源码历史。
2. 面向国内普通粉丝/用户，要求无梯子极速秒开（国内 CDN 加速）。
3. 纯人工可控：平时开发/打包测试/打内测包，线上用户 100% 静默绝不弹窗。
4. 视频引流：作者在 B站/抖音等平台发布新版本视频后，一键全网推送，引导旧版用户跳转观看新视频。
5. 多项目复用：一个腾讯云/阿里云对象存储桶，可以管理作者名下所有不同的软件。

--------------------------------------------------------------------------------
一、云端基础设施准备（只需配置一次，所有项目通用）
--------------------------------------------------------------------------------

1. 创建对象存储桶（以腾讯云 COS 为例，阿里云 OSS 同理）：
   - 进入控制台：https://console.cloud.tencent.com/cos
   - 新建存储桶（Bucket），例如命名为：`app-releases-125xxxxxxx`
   - 地域选择：国内任意节点（如上海、广州、北京）
   - 【核心权限设置】：访问权限必须选择「公有读、私有写」！
     * 公有读：全世界粉丝的手机无需登录即可读取 version.json。
     * 私有写：只有持有密钥的作者本人/自动化脚本才能修改发布内容，其他人绝对无法篡改。

2. 多软件目录规划：
   在同一个存储桶根目录下，为不同软件创建独立文件，例如：
   - 翻译软件：`translate/version.json`
     对应访问链接：https://[你的存储桶域名]/translate/version.json
   - 另一个小工具：`tool_b/version.json`
     对应访问链接：https://[你的存储桶域名]/tool_b/version.json

3. 准备自动化发布密钥（API 密钥）：
   - 在腾讯云右上角头像 ->「访问管理」->「API 密钥管理」
   - 点击新建密钥，获取两串字符：
     * SecretId （公钥标识）
     * SecretKey（私钥密码，妥善保管，勿推送到公共仓库）

--------------------------------------------------------------------------------
二、版本配置文件标准格式 (version.json)
--------------------------------------------------------------------------------

每个软件在云端对应的 version.json 结构极其纯净轻量（几百字节）：

{
  "versionCode": 2,
  "versionName": "v0.2.0",
  "title": "🎉 发现全新版本！",
  "message": "本次更新优化了核心性能，新增一键快捷操作。快来看看 UP 主的最新演示视频吧！",
  "videoUrl": "https://www.bilibili.com/video/BV1xxxxxx",
  "minSupportedCode": 1,
  "forceUpdate": false
}

【字段含义解析】：
- versionCode: 核心比较字段（整数，递增）。只要这个数字大于用户手机里 App 的 versionCode，App 就会弹窗提醒。
- versionName: 展示给用户看的版本号（如 v0.2.0）。
- title: 弹窗标题。
- message: 弹窗说明文字 / 更新亮点。
- videoUrl: 点击“去看看 / 立即更新”时跳转的链接（直接填 B站视频或动态链接，App 会自动唤起 B站或浏览器打开）。
- forceUpdate: 是否强弹（可选，true 时用户必须点跳转或退出，false 时提供“稍后提醒”按钮）。

--------------------------------------------------------------------------------
三、客户端（Android App）实现规范（直接提供给开发人员/AI）
--------------------------------------------------------------------------------

在 App 项目中实现以下三部分即可：

1. 触发检查时机：
   - 启动静默检查：MainActivity 启动时，后台发起静默 HTTP GET 请求读取 version.json。
   - 频次限制（防滥用）：本地使用 SharedPreferences / DataStore 记录上次检查时间，建议每日最多自动检查 1 次（启动时），避免频繁打扰用户；或者在每次冷启动时检查。
   - 手动检查入口：在“设置”或“关于”界面保留一个“检查新版本”按钮，点击后立即无视频次限制强制发起检测。

2. 版本比较逻辑：
   val currentCode = BuildConfig.VERSION_CODE
   if (remoteInfo.versionCode > currentCode) {
       // 弹出升级提示对话框
   } else {
       // 如果是手动点击检查：提示“当前已是最新版本”
       // 如果是启动静默检查：什么都不做，完全静默
   }

3. UI 交互与跳转：
   - 弹窗展示：标题、更新内容（message）、两个按钮【去看看新视频】和【暂不更新】。
   - 点击【去看看新视频】的跳转逻辑：
     val intent = Intent(Intent.ACTION_VIEW, Uri.parse(remoteInfo.videoUrl))
     context.startActivity(intent)
     * 系统会自动优先使用手机上安装的 Bilibili App 打开，若没安装则自动调用手机浏览器打开。

4. 异常与离线容错：
   - 如果用户处于断网、弱网或请求超时状态：捕获所有异常，静默忽略，绝不导致应用闪退或阻碍正常使用。

--------------------------------------------------------------------------------
四、日常运维与发布工作流（作者视角）
--------------------------------------------------------------------------------

【平时阶段：开发、调优、自测】
- 本地代码该怎么改就怎么改，电脑上重新编译打包任意多次。
- 云端的 versionCode 保持不动（比如当前线上正式版是 1，云端就是 1）。
- 粉丝打开手机里的版本 1：1 == 1，没有任何更新提示，安安静静。

【发版阶段：视频制作完成，决定全网推送】
1. 打包正式版 APK：把工程的 versionCode 升到 2，编译出正式 APK。
2. 发布新视频：在 B站发布新演示视频，把新 APK 放到置顶评论或简介的网盘链接中。
3. 复制视频链接（如 https://b23.tv/xxxx）。
4. 触发推送（二选一）：
   - 方式 A（全自动）：在 Claude/AI 对话中发指令：“帮我推送 [软件名] 新版本，视频链接是 xxx，更新说明是 yyy”，由本地脚本自动调用腾讯云 API 覆盖更新 version.json。
   - 方式 B（手动）：登录腾讯云网页控制台，编辑该软件的 version.json，将 versionCode 改为 2，填入新视频链接保存。
5. 结果：
   几秒钟内全网 CDN 缓存刷新。所有之前安装了版本 1 的粉丝，下一次打开 App 时就会自动弹出精美的推荐弹窗，一键跳转到你的新视频！
